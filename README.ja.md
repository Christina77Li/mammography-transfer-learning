# マンモグラフィ画像分類における転移学習

[English](README.md) | 日本語

[![CPU validation](https://github.com/Christina77Li/mammography-transfer-learning/actions/workflows/tests.yml/badge.svg?branch=main)](https://github.com/Christina77Li/mammography-transfer-learning/actions/workflows/tests.yml)

ImageNet で事前学習した **ResNet101** を対象に、クラス不均衡が非常に大きい RSNA スクリーニングマンモグラフィデータセットで 4 種類のファインチューニング戦略を比較したプロジェクトです。学習初期のクラス分布と、バックボーンを段階的に適応させる方法が、画像単位のがん分類にどう影響するかを検証しています。

研究の概要は[発表スライド（PDF）](docs/slides/research_presentation.pdf)をご覧ください。

## 本プロジェクトの特徴

- **データの整合性**：学習前に CSV と PNG の対応を確認し、乳房グループ単位の分割に重複がないことを検証します。
- **チェックポイントのトレーサビリティ**：重みの引き継ぎやステージ間のロールバックを行っても、重み・指標・エポックの対応が崩れません。
- **エンジニアリング面の検証**：学習コードをモジュール化し、回帰テストと ResNet101 のスモークテストを CI で実行しています。

## 結果

各実験行の ROC-AUC、PR-AUC（AP）、検証損失は、同じチェックポイントから得た値です。4 つの実験の損失は、いずれも陽性重み付き BCE（`pos_weight ≈ 6.76`）です。

| 実験 | 学習戦略 | ROC-AUC ↑ | PR-AUC (AP) ↑ | 検証損失 ↓ |
| --- | --- | ---: | ---: | ---: |
| Exp1 | ベースライン：全データで直接ファインチューニング | 0.5780 | 0.0242 | 0.4115 |
| Exp2b | 1:3 サブセットでのウォームアップ → 全データへ移行 | 0.6591 | 0.0426 | 0.4341 |
| Exp3 | 段階的アンフリーズ | 0.6601 | **0.0486** | 0.4062 |
| Exp4 | ウォームアップ → ヘッド再調整 → 段階的アンフリーズ | **0.6711** | 0.0482 | **0.3980** |
| ランダム基準 | 検証データの陽性率 2.02% に基づく無情報の基準値 | 0.5000 | ≈ 0.0202 | — |

![学習戦略別の検証結果](results/figures/strategy_comparison.png)

Exp1 の AP はランダム基準をわずかに上回る程度です。Exp4 の AP はランダム基準の約 2.38 倍ですが、これは平均適合率の比較であり、臨床での検出率を示すものではありません。比較したチェックポイントの中では、Exp4 の ROC-AUC が最も高く、検証損失が最も低くなりました。PR-AUC は Exp3 が最も高い値でした。ROC-AUC が最も高かったステージは、Exp3 では **layer2**、Exp4 では **layer3** です。学習ステージと追加のチェックポイントについては[実験の詳細](docs/experiments.md)（英語）をご覧ください。

## 学習の設計

ウォームアップでは、学習データのグループから陽性を多めに含むサブセットを抽出して使います。Exp2a ではモデル全体を更新し、Exp4 のウォームアップではヘッドのみを更新します。検証には常に全検証データを使います。段階的アンフリーズでは、まずヘッドだけを学習し、その後 `layer4 → layer3 → layer2 → layer1 → conv1` の順にブロックを解放します。浅いブロックほど学習率を小さくし、ステージを切り替えるときは選択したチェックポイントへロールバックします。

学習パイプラインでは、AdamW、フェーズごとの BCE 系損失、プラトー時の学習率スケジューリング、検証損失の制約付きチェックポイント選択を使っています。Exp3 と Exp4 では BatchNorm の統計量を固定しています。ウォームアップの損失は通常の BCE なので、重み付き BCE を使う全データ学習の損失とは直接比較できません。

## クイックスタート

**Python 3.12・CPU**：仮想環境を作成してから、次のコマンドを実行します。

```bash
python -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements-dev.txt
python -m pytest -q
python scripts/smoke_test.py
```

スモークテストでは、合成 PNG 画像で ResNet101 を 1 エポック学習し、チェックポイントを再読み込みして指標を確認します。データセットや事前学習済み重みのダウンロードは不要です。Windows 用のコマンド、CUDA 環境の構築、入力データの準備は[セットアップ手順](docs/setup.md)（英語）をご覧ください。

手元のデータセットで学習する場合：

```bash
python scripts/train.py --config configs/exp1_baseline.yaml --check
python scripts/train.py --config configs/exp1_baseline.yaml --output-dir outputs/exp1_new_run
```

Exp2 と Exp4 の設定は CUDA を前提としているので、必要に応じて `--device cpu` を付けてください。Exp3 は利用可能なデバイスを自動で選択します。Exp2b を実行するには、選択済みの Exp2a チェックポイントが必要です。パスはプロジェクトのルートを基準に解決されます。実行ごとに新しい出力ディレクトリを指定してください。

## 評価の範囲とプロジェクト構成

- 結果はいずれも 1 回の学習で得た検証データ上の値で、信頼区間、有意差検定、外部検証は含みません。
- 分割は **患者 ID ＋ 左右（ラテラリティ）** 単位です。同じ乳房の複数の撮影ビューは同じ区分に入りますが、同じ患者の左右の乳房が必ず同じ区分に入るとは限りません。
- 本結果は臨床スクリーニングでの性能を示すものではありません。
- 検証データは学習率のスケジューリング、ステージの切り替え、チェックポイントの選択にも使っています。そのため、これらのスコアは検証データ上の結果であり、未使用のテストデータで得た推定値ではありません。
- ステージごとの学習率と損失の許容幅は実験上の設定であり、最適値であることは確認していません。
- 入力画像は**計算資源の制約により 256 × 256** に縮小しています。小さな病変や石灰化の判別に必要な細部が失われる可能性があります。
- 今後の課題は、高解像度またはパッチベースの入力、患者単位の分割、未使用のテストデータでの評価、複数シードでの検証です。
- 設定はすべて `deterministic: false` です。シードを固定しても、特に GPU では再実行の結果が変わることがあります。

| パス | 内容 |
| --- | --- |
| `configs/` | 実験設定 |
| `src/` | データ読み込み、モデル、学習、評価 |
| `scripts/` | 学習、DICOM 変換、スモークテスト、グラフ作成 |
| `tests/` | データ・設定・チェックポイントの回帰テスト |
| `results/` | 実験の指標とグラフ |
| `docs/` | セットアップ、実験、チェックポイントの仕様（英語） |

グラフは `python scripts/plot_reported_results.py` で再生成できます。データセット、モデルの重み、実行時の出力は Git に含めていません。学習の実行経路は[学習アーキテクチャ](docs/training_architecture.md)、チェックポイントの選択と重みの引き継ぎは[チェックポイントの仕様](docs/config_and_checkpoints.md)、自動テストは[テストの説明](docs/verification.md)をご覧ください（いずれも英語）。
